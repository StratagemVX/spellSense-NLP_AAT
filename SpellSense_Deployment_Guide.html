2. How the Connection Was Implemented

The frontend API service originally used the local development address when no environment variable was supplied:

http://127.0.0.1:8000/api

That address works only on the developer machine. It was changed to the deployed Render API as the production fallback:

const API_BASE_URL = import.meta.env.VITE_API_URL
  || 'https://spellsense-nlp-aat-2.onrender.com/api';

All frontend service calls build on this base URL:

  • POST /api/correct for full text correction
  • POST /api/analyze-word for single-word analysis
  • GET /api/examples for example content
  • GET /api/health for the navigation-bar service status

The Render backend already enabled CORS with allow_origins=["*"], so browser requests from Netlify are accepted.

3. Netlify Deployment

  1. Built the frontend from the frontend directory with npm run build.
  2. Added frontend/netlify.toml with the build command and dist publish directory.
  3. Added an SPA redirect so React Router routes resolve to index.html on refresh.
  4. Created the Netlify project spellsense-nlp-aat.
  5. Published the production build to Netlify.
[build]
  command = "npm run build"
  publish = "dist"

[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200
Live result: https://spellsense-nlp-aat.netlify.app returned HTTP 200 after deployment.

4. Vercel Preparation

A frontend/vercel.json file was added with the same single-page application rewrite:

{
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}

The Vercel CLI was installed, but no Vercel account credentials were available in the terminal session. Therefore the project is prepared for Vercel, but the final command requires account login:

cd frontend
vercel login
vercel --prod
